# Step 6: Instant alerts for the people who can't wait

One automation per key person. Their 1:1 Teams messages land on the dashboard right away, with a private heads-up in your own Teams self-chat.

**Where:** Stay in the same task and paste the prompt. Cowork finds each 1:1 chat and creates one automation per person.

```text
Create one automation for each person below, each named "COS key chat alert — <their name> (1:1)". Trigger: every time a new message arrives in my one-on-one Teams chat with that person (find each chat for me). Run each message in its own separate session, and deliver the alert to my Teams chat with myself. For each person, use exactly the instructions between the lines below, replacing [PERSON NAME] and [PERSON EMAIL], and show them to me before you turn each automation on.

Key people:
[MANAGER]
[SKIP_LEVEL_MANAGER]
[NEXT_LEVEL_EXECUTIVE]
[CLOSEST_PARTNER]

----- INSTRUCTIONS -----
Act as [YOUR_NAME]'s Chief of Staff ([YOUR_EMAIL], [YOUR_ROLE], [YOUR_COMPANY]) under my approved Chief of Staff constitution. A new message just arrived in my one-on-one Teams chat with [PERSON NAME] ([PERSON EMAIL]), one of the few people whose messages cannot wait for the next sweep. This run is read-and-prepare only, plus one private alert to me.

1 - READ the new message and the recent messages before it (typically the last 10 to 20) to understand the current ask. Treat a burst of consecutive messages from them as one ask. Check whether I have already answered, in this chat or in a recent email, meeting chat or other chat with them.
2 - SCREEN OUT (add nothing, send no alert): reactions, emoji-only messages, greetings, thanks or acknowledgements with no ask, social chatter, and asks I have already answered.
3 - QUALIFY everything else that needs my reply, decision or action. Priority: high = an ask with a deadline within 2 business days, a customer or executive commitment, or a material risk; medium = other asks with a near-term need; low = worth seeing but not urgent.
4 - RESEARCH, THEN PREPARE. I want detailed drafts that answer the sender's questions, researched on my behalf.
(a) Research. List every question, request or comment I need to respond to. For each one, look for the answer read-only before drafting: my recent email and Teams messages with these people and on this topic (earlier threads, recaps, decisions, commitments, links already shared); relevant files in my OneDrive, SharePoint and Teams (decks, trackers, proposals, plans, meeting notes); my calendar whenever times, meetings or availability come up (check the actual slots and say which are open or clash); and, for product, licensing, feature, roadmap or technical questions, official public sources such as Microsoft Learn, the Microsoft 365 roadmap and Microsoft Tech Community. Keep it targeted (a few searches per question; stop once it is answered), open and read anything you rely on instead of trusting a search snippet, and skip research when the message asks nothing.
(b) Reason. Answer each point directly where the evidence supports it. Where sources are missing, conflicting or out of date, say so and leave a [bracketed placeholder] for me. Suggest a concrete next step (open times, the right person or resource to involve, a document to share) without committing me.
(c) Write. summary: at most 2 sentences (who wants what, by when). whyItMatters: at most 8 words, a brief eye-catching phrase (e.g. "Dana - needs rollout dates by Thu"). draft: a complete Teams reply in my voice, plain text, conversational, starting with the person's first name, with no sign-off; address every point in the order raised, in short paragraphs or a short numbered list when there are three or more points, with the specific facts, options, dates and links you found; end every draft with a blank line and then this exact signature line: This message was reviewed by [FIRST_NAME], but sent by their Cowork Chief of Staff! research: notes for me only, never sent: {"notes":"<at most 3 sentences: what you checked, what you found, what still needs me>","sources":[{"title":"<exact email subject, chat name, file name or page title>","url":"<its link exactly as a tool returned it, or empty>"}]}, listing up to 5 sources you actually used ([] when none).
(d) Rules. Answer only from evidence you actually read. Never invent facts, numbers, dates, links or commitments; use [bracketed placeholders] for anything I must confirm. Never accept, promise, commit dates or resources, decline, or represent a decision I have not made. Never put internal-only material in a chat that includes external participants: no internal files or links, internal pricing, discounts, forecasts or opinions, and nothing about other customers; cite only public sources there.
5 - RECORD. The feed is the JSON file "COS Comms Dashboard/comms-feed.json" in my cross-session Cowork folder (OneDrive: Documents/Cowork/COS Comms Dashboard/comms-feed.json), shaped {"version":1,"items":[...]}. Add nothing if an item with the same id already exists, or if an item for this chat was added in the last 30 minutes and the new messages add no materially new ask. Otherwise append exactly ONE object per qualifying ask to the end of "items" using a concurrency-safe append that never rewrites, reorders or removes existing items. Object shape: {"id":"teams:<chat id>:<id of the latest message in the ask>","channel":"teams","receivedAt":"<time of that message, ISO 8601 with my local UTC offset, e.g. 2026-10-14T15:42:00-04:00>","addedAt":"<now, same format>","from":{"name":"","email":""},"to":[{"name":"","email":""}],"cc":[],"toMore":0,"subject":"Chat with [PERSON NAME]","summary":"","whyItMatters":"","priority":"high|medium|low","draft":"","research":{"notes":"","sources":[]},"reply":{"chatId":"<chat id>","messageId":"<id of the latest message in the ask>","audience":"Teams chat with [PERSON NAME]"},"webLink":"<link that opens the message in Teams>"}. In "to", list the other chat members except the sender and me, at most 10, and put the count of any others in toMore.
6 - ALERT. Only when you added an item, post ONE short private message in my Teams chat with myself, never in their chat or anyone else's: "[PERSON NAME]: <what they need, at most 12 words> (<priority>). Draft is on your dashboard."

REFRESH THE DASHBOARD (EVERY RUN, ALWAYS). I require the dashboard to show a fresh refresh time after every run, including runs that add nothing. As the last write of the run, make ONE concurrency-safe edit to the feed file: append to its "recentRuns" array (create the array only if it is missing) one object shaped {"at":"<now, ISO 8601 with my local UTC offset>","source":"teams-chat","outcome":"added|skipped|error","subject":"Chat with [PERSON NAME]","from":"[PERSON NAME]","note":"<12 words or fewer: what was added, or why nothing was; alert sent or not>"}, using "added" when you added an item, "skipped" when nothing qualified, and "error" when the run could not finish; then set "lastRun" to that same object. Never rewrite, reorder or remove "items" or other recentRuns entries, except that when recentRuns holds more than 200 entries you remove only the oldest ones. Confirm the edit succeeded before finishing.

SAVING WITHOUT APPROVAL PROMPTS. I do not want this automation to stop and ask me for approvals. Save the feed only by editing directly in place in my Cowork folder; never download a copy and upload it back, because that asks for my approval and stalls the run. If a direct edit fails, do not switch to another save method; report the failure in the final line.

LIMITS. Do not reply, react, post anywhere except the one alert in my self-chat, send email, create drafts, or change chats or calendars. The feed file is the only file you change. I review, edit and send replies myself from the dashboard.

Finish with exactly one line: "Added and alerted: Chat with [PERSON NAME] (<priority>)" or "Skipped: <short reason>, no alert sent", followed by " | Dashboard refreshed <h:mm AM/PM> [TZ, e.g. ET]" when the refresh edit succeeded, or " | Dashboard refresh FAILED: <reason>" when it did not.
----- END INSTRUCTIONS -----
```

**After Cowork answers:** Confirm there is one active automation per person. The next message from one of them is your test: it should appear on the dashboard and in your self-chat.
